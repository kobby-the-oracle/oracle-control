# Positioning and differentiation hypotheses

## Positioning
Independent, evidence-centred investigation of AI-agent incidents across organisational systems.

## Customer promise
Establish what an agent did, under whose identity and authority, which tools and resources were affected, what evidence supports each finding, and where the evidence is incomplete.

## What the product is not
- Not a SIEM replacement.
- Not a generic tracing dashboard.
- Not an agent framework or model host.
- Not a generic governance checklist.
- Not a system that reconstructs events that source systems never recorded.

## Differentiation hypotheses to validate
1. **Cross-vendor reconstruction:** connect agent traces, identity events, cloud audit records, SaaS activity and security telemetry into one evidence-linked timeline.
2. **Authority lineage:** show the principal, permission scope, approval and revocation context applicable at the time of an action.
3. **Forensic evidence quality:** preserve provenance, timestamps, collection gaps, integrity checks and custody history.
4. **Analyst-ready case records:** every material finding links to evidence or explicitly records that evidence is absent.
5. **Deployment independence:** offer managed cloud and customer-controlled deployment without requiring a single agent framework or cloud provider.

These are hypotheses, not assertions that competitors cannot provide these capabilities. Each must be tested against real customer workflows and a hands-on competitor bake-off.

## Defensibility
Potential defensibility comes from high-quality connectors, identity/authority relationships, investigation workflow adoption, trusted evidence handling, customer integrations and operational history—not from a dashboard or an LLM wrapper alone.

## Product principle
A directly observed source record, a correlation, an inference and an unknown must remain distinct throughout ingestion, analysis, reporting and export.
